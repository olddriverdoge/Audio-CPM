# 曲库目录修复：多目录、标题栏与滑动返回（0.5.20/100）

## 问题与修复

1. **多目录选不进去 / 只能保存最后一个**
   - 原因：曲库浮窗每 1.8 秒轮询 `/api/library/state`，`refreshState()` 每次都把服务端 `dirs` 覆盖到本地草稿 `selectedDirs`。用户添加第一个目录后，等下一轮轮询就会把草稿清空；再添加第二个并保存时，只剩最后一个。
   - 修复：增加 `setupDirty` 草稿标记。目录编辑面板打开且用户已改过目录时，轮询只更新扫描状态，不覆盖草稿；取消/关闭面板时丢弃草稿并恢复服务端目录，保存成功后才以服务端结果为准。
   - 添加目录的选择器现在优先从当前浏览目录开始，不再固定从第一个已选目录开始，方便连续添加多个音乐文件夹。

2. **首次引导遮罩盖住曲库标题栏**
   - 原因：`#lib-setup` / `#lib-picker` 使用 `position:absolute; inset:0`，首次进入时目录引导覆盖整个浮窗，标题栏被遮住，无法拖动/收起，看起来像“没有标题”。
   - 修复：遮罩从标题栏下方 25px 开始，标题栏始终可见、可拖动、可点“—”收起；目录卡片仍在剩余区域内滚动。

3. **目录浏览返回上级**
   - 目录选择器列表支持左右滑动返回上级，纵向滚动不受影响；滑动后 450ms 内抑制误点击。
   - 移除“↑ 上级”按钮，标题下方增加“左右滑动返回上级”提示。

## 验证

- 云端完整回归：API **59/59** + UI **47/47** = **106/106**，控制台 0 报错。
- 新增 UI 回归 `library keeps multiple selected dirs`：

  - 添加第一个目录后等待超过一轮 1.8 秒轮询，目录仍在；
  - 打开目录选择器，确认“上级”按钮已移除；在列表上左滑回到父目录；
  - 选择第二个目录，再等待一轮轮询，两个目录都保留；
  - 保存后 `/api/library/state` 返回 2 个目录，扫描完成且曲目数 ≥5。
